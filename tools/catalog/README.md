# Наполнение каталога: набор товаров с 3D‑моделями

Пока настоящего каталога нет, библиотеку можно наполнить открытыми 3D‑моделями — без ручной загрузки через админ‑панель и без расхода лимитов Vercel.

Как это устроено:

1. **Набор собирается на вашем компьютере.** Скрипт отбирает мебель в источнике, скачивает модели по одной, сжимает и складывает в папку: `manifest.json`, `models/`, `images/`.
2. **Файлы набора публикуются как обычная статика** — в `public/` проекта или на любом хостинге. Vercel Blob не используется.
3. **Товары записываются в базу напрямую**, тем же кодом каталога, что работает на сервере. Функция Vercel не участвует, поэтому её пределы (4,5 МБ на запрос, 60 секунд) не мешают.

Набор переносим: при переезде с Vercel на свой сервер тот же `import` заливает его в локальную базу.

## Установка

Нужен Node 22.5+.

```bash
cd tools/catalog
npm install        # sharp (текстуры) и gltfpack (сжатие геометрии)
```

Для записи в базу сайта на Vercel нужен ещё `npm install` в корне проекта (драйвер Neon).

## Порядок действий

Команды запускаются из корня проекта.

```bash
# 1. Посмотреть, сколько моделей подойдёт. Скачиваются только метаданные (~100 МБ), модели — нет.
node tools/catalog/cli.mjs abo-plan

# 2. Проба на 20 моделях.
node tools/catalog/cli.mjs abo-build --limit 20

# 3. Проверить пробу локально: записать в локальную базу и открыть редактор.
node tools/catalog/cli.mjs import --upload
node server/index.js            # http://localhost:8080/editor

# 4. Собрать всё (или часть: --per-type 200, --types sofa,chair,bed, --max-mb 900).
node tools/catalog/cli.mjs abo-build

# 5. Опубликовать папки models/ и images/ (см. «Где разместить файлы») и записать товары в базу сайта.
vercel env pull .env.local
node --env-file=.env.local tools/catalog/cli.mjs import --base-url https://<адрес-файлов> --drop-generated
```

`--drop-generated` заодно убирает прежние сгенерированные демо‑товары без моделей («Диван Nord S» и подобные), чтобы они не смешивались с настоящими.

Сборку можно прерывать и запускать снова — готовые модели не обрабатываются повторно. `import` тоже повторяем: те же товары обновляются, а не задваиваются.

Перед записью `import` печатает, в какую базу он пишет (локальный SQLite или Neon). `--dry-run` только проверяет набор.

### На что смотреть после пробы

- **Куда смотрит «перед» модели.** Редактор считает передом ось +Z. Если диваны стоят спинкой к комнате, пересоберите с `--rotate-y 180` (после `rm -rf catalog-pack`).
- **Что отсеялось.** `catalog-work/abo-skipped.csv` — список пропущенных моделей с причинами. Правила отбора лежат в `lib/mapping.mjs`; тип, который стоит добавить, виден в сводке `abo-plan`.

## Набор в самом проекте: импорт не нужен

Если набор лежит в `public/catalog-pack`, сервер сам записывает его товары в базу при запуске — и локально, и на Vercel. Достаточно собрать набор в эту папку и выложить вместе с проектом:

```bash
node tools/catalog/cli.mjs abo-build --pack public/catalog-pack --max-mb 300
git add . && git commit -m "catalog pack" && git push
```

- Набор сверяется по отметке в `manifest.json`: пока он не менялся, запуск сервера стоит одного запроса к базе.
- Товары, исчезнувшие из набора, из каталога убираются.
- Кнопка «Удалить демо» в админ‑панели убирает сгенерированные демо‑товары, а набор сразу записывает заново. Чтобы убрать и набор, сначала удалите его папку из проекта.

Команда `import` нужна только когда файлы набора лежат в другом месте.

## Где разместить файлы

| Размер набора | Куда | Параметр импорта |
|---|---|---|
| до ~300 МБ | в проект: `--pack public/catalog-pack` при сборке | не нужен — см. выше |
| больше | любой статический хостинг с CORS, например Cloudflare R2 | `--base-url https://…` |
| свой сервер после переезда | хранилище платформы, `data/uploads` | `--upload` |

**Почему не Vercel Blob.** На бесплатном тарифе это 1 ГБ и 2 000 операций записи в месяц, каждый загруженный файл — операция. При превышении хранилище отключается на 30 дней, и сайт остаётся без файлов. Поэтому `--upload` при подключённом Blob отказывается работать.

Внешний хостинг должен отдавать заголовок `Access-Control-Allow-Origin`: редактор загружает модели запросом с другого домена.

## Объёмы

- Исходные модели ABO тяжёлые: архив на 154 ГБ содержит около 7,9 тыс. моделей, в среднем ~20 МБ на модель. Скачивается по одной, исходник после обработки удаляется, но трафик и время на полный набор — существенные.
- После сжатия модель весит примерно 0,2–1,2 МБ при текстурах 1024 пикселя (замер на образцах Khronos). `--tex 512` заметно уменьшает набор.
- На одну модель уходит около секунды обработки плюс время скачивания.

## Свои модели

```bash
node tools/catalog/cli.mjs local-build --in <папка с .glb>
```

Категория определяется по имени файла. Точнее — описать модели в `items.json` в той же папке:

```json
[{ "file": "sofa.glb", "typeId": "sofa", "name": "Диван Осло", "brand": "Nord", "price": 1690, "currency": "BYN",
   "colors": ["серый"], "materials": ["ткань"], "styleTags": ["скандинавский"], "image": "sofa.jpg" }]
```

Идентификаторы категорий — в `public/shared/catalog-types.js`.

## Что делает обработка

- Подбирает категорию и форму платформы, размеры товара берёт из габарита модели.
- Приводит модель точно к этим размерам: сервер сверяет модель с размерами товара с допуском 2 % или 5 мм.
- Уменьшает текстуры и переводит их в WebP.
- Упрощает сетку до `--tris` треугольников и сжимает геометрию (gltfpack, `EXT_meshopt_compression`).

Редактор и серверная проверка GLB умеют читать такие модели начиная с этого изменения.

## Оговорки

- **Цены условные.** В открытых наборах цен нет; цена считается из категории, размера и бренда, чтобы ИИ‑дизайнеру было из чего выбирать по бюджету.
- **Названия на английском**, как в источнике. Цвета, материалы и стили переведены в словарь платформы.
- **Угловые диваны и шкафы** попадают в каталог как прямые: по габариту нельзя понять, с какой стороны угол.
- **Лицензия ABO.** Страница набора указывает CC BY 4.0, реестр открытых данных AWS — CC BY‑NC 4.0 (некоммерческое использование). Проверьте условия до показа заказчику; указание источника обязательно в обоих случаях.
- **Удаление.** Товары набора помечены как «Демо»: кнопка «Удалить демо» в админ‑панели убирает их все.
- **gltfpack из npm** работает медленнее и с меньшим пределом памяти, чем нативный. Путь к нативной сборке можно задать переменной `GLTFPACK`.
