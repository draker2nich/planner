# Стенд и сквозная проверка ИИ‑дизайнера

Здесь два инструмента. Оба запускаются из корня проекта и ничего не меняют в рабочей базе: сервер поднимается на временной папке данных.

## Стенд: насколько хорошо модель расставляет мебель

```
AI_API_KEY=…  node tools/ai-eval/eval.cjs        # настоящая модель, расходует токены
AI_MOCK=1     node tools/ai-eval/eval.cjs        # заглушка: проверить, что путь генерации работает
```

Стенд прогоняет сценарии из `scenarios.cjs` (гостиная, спальня, столовая, «только замена», комната буквой Г) через весь путь
генерации без браузера: сервер — в этом же процессе, геометрия — тот же код редактора (`public/js/editor/ai`).
Каталог берётся из `public/catalog-pack`.

Что получается на выходе (`tools/ai-eval/out`, папка в `.gitignore`):

- `report.json` — по каждому варианту: построен ли, сколько предметов переставлено, скольким место подбирала программа,
  был ли повторный запрос к модели, сколько взято запасных товаров, замечания, время и расход токенов;
- `<сценарий>-base.svg`, `<сценарий>-v1.svg`, `<сценарий>-v2.svg` — планы: исходная расстановка и оба варианта
  (синим выделено изменённое, точка на предмете — его лицевая сторона). Качество расстановки оценивается глазами по ним;
- с ключом `--dump` — тексты каждого запроса к модели и её ответы (`call-NNN-request.txt`, `call-NNN-response.json`):
  по ним настраиваются формулировки запросов в `server/core/designer.js`.

Параметры: `--only living,bedroom`, `--runs 3`, `--again`, `--refine`, `--out DIR`, `--dump`, `--min-built 0.9`, `--max-auto 0.25`.

Пороги приёмки (код выхода 1, если не выдержаны):

- `--min-built` — доля построенных вариантов. Вариант «не построен», когда предмет некуда поставить даже программе
  или модель не ответила;
- `--max-auto` — доля предметов, которым место пришлось подбирать программе: модель предложила положение,
  которое не прошло проверку и после повторного запроса. Чем выше доля, тем меньше в расстановке замысла модели;
- нарушения правил расстановки в построенном варианте (предмет в зоне двери, перед окном без замечания и т. п.) —
  всегда ошибка: это означало бы сбой программы, а не модели.

На заглушке цифры качества ничего не значат — она расставляет по простым правилам. Пороги по умолчанию — отправная точка;
их стоит уточнить после первых прогонов на настоящей модели.

## Сквозная проверка в браузере

```
cd tools/ai-eval && npm install && npx playwright install chromium && npm run e2e
```

Поднимает сервер с заглушкой модели (`AI_MOCK=1`), регистрирует пользователя и проходит в браузере весь путь:
мастер (права, пожелания) → генерация → экран результата → вариант на плане и в 3D → правка в варианте → доработка →
«вернуть прежние» → «заново» → выбор → перезагрузка страницы → переход к стенам с удалением вариантов.
Снимки экрана — в `tools/ai-eval/shots`.

Переменные: `E2E_HEADED=1` — показать окно браузера; `E2E_CDN_DIR` — папка с `three.min.js`, `GLTFLoader.js`,
`meshopt_decoder.js`, если CDN недоступны; `PLAYWRIGHT_PATH` — путь к уже установленному пакету `playwright`.
