# furnitech — планировщик комнаты

Редактор плана комнаты (2D и 3D), каталог мебели, ИИ‑дизайнер, заявки менеджеру и админ‑панель.
Без фреймворка и сборки: статические страницы в `public/`, API — в `server/core/` (один код для локального сервера и для функции Vercel).

## Запуск локально

Нужен Node.js ≥ 22.5. Зависимости для локального режима не нужны: база — SQLite (`node:sqlite`), файлы — в `./data`.

```bash
cp .env.example .env          # по желанию: без .env всё работает со значениями по умолчанию
node --env-file=.env server/index.js      # без .env: npm start
```

- сайт — http://localhost:8080/, редактор — `/editor`, админ‑панель — `/admin`;
- администратор создаётся при первом запуске: логин и пароль — в `data/admin-credentials.txt` (или задайте `ADMIN_EMAIL` / `ADMIN_PASSWORD`);
- письма без почтового ключа пишутся в `data/outbox/`;
- `AI_MOCK=1` включает ИИ‑дизайнер на заглушке, без ключа и расходов.

## Проверки

```bash
npm test          # node --test, без внешних зависимостей; база и файлы — во временной папке
```

Тесты лежат в `server/test/` и в сборку сайта не попадают (на Vercel публикуется только `public/` и функция `api/`).

## Развёртывание на Vercel (как сейчас)

1. `npm install` один раз локально и закоммитить `package-lock.json` — версии зависимостей закреплены в `package.json`, lock‑файл закрепляет и их зависимости.
2. В проекте Vercel подключить Postgres (Neon) и Blob — появятся `DATABASE_URL` и токен Blob.
3. Задать `ADMIN_EMAIL`, `ADMIN_PASSWORD` (от 12 символов), при необходимости — почту, вход через Google/Яндекс и ключ ИИ. Полный список — в `.env.example`.
4. Схема базы обновляется сама при первом запросе после выкладки (`server/core/db.js`, миграции по версиям).

Обновляя `@vercel/blob`, поменяйте версию и в `public/admin.html` (функция `loadBlobClient`): браузерная часть загрузки берётся с CDN той же версии.

## Устройство

| Путь | Что там |
| --- | --- |
| `server/core/app.js` | маршруты API, лимиты, сборка окружения |
| `server/core/*.js` | пользователи и сессии, проекты, каталог, фото, заявки, почта, ИИ‑дизайнер |
| `server/index.js` | локальный HTTP‑сервер: статика (кэш, сжатие), заголовки безопасности, вызов ядра API |
| `api/index.mjs` | та же точка входа для Vercel (одна функция на весь `/api/*`) |
| `public/*.html` | страницы: главная, вход, проекты, аккаунт, редактор, админ‑панель, документы |
| `public/js/editor/` | редактор: обычные скрипты с общей областью видимости, порядок подключения — в `editor.html` |
| `public/shared/` | общие стили, шрифт, проверки полей, сессия, типы каталога (используются и сервером) |
| `public/vendor/three-r128/` | three.js r128 с загрузчиком glTF (лицензия MIT — рядом) |
| `tools/` | подготовка набора каталога и сквозная проверка ИИ‑дизайнера |

## Что важно знать при сопровождении

- **Сессии** — токен в `Authorization: Bearer`, в базе лежит только его SHA‑256. Сеанс пользователя — 30 суток, администратора — 7 (`ADMIN_SESSION_DAYS`).
- **Лимиты** — таблица `rate_limits`; попытка занимается одним запросом (`limiter.take`), поэтому параллельные запросы лимит не обходят.
- **Каталог** отдаётся порциями (`/api/catalog/products?limit=&offset=&images=1`) с `ETag` и кэшем CDN на минуту: новый товар появляется в редакторе с задержкой до минуты.
- **Корзина проектов** — 30 суток, не больше 30 проектов на пользователя.
- **CSP** работает в режиме отчёта. На своём сервере её можно включить всерьёз: `CSP_ENFORCE=1` (сначала проверьте все страницы; в `vercel.json` режим меняется названием заголовка).
- **Свой сервер за прокси** — обязательно `TRUST_PROXY` (см. `.env.example`), иначе лимиты считаются по адресу прокси. Адрес сайта зашит в `public/index.html` (canonical, Open Graph), `public/sitemap.xml` и `public/robots.txt`.
